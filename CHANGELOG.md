## Unreleased

### Fixed

- `render-agent-commands.ts`: the description-folding filter dropped every
  `[cc: alias]` line before its prefix could be stripped, truncating or
  falling back to a generic description for all 21 generated Codex skills and
  Gemini TOML commands. The frontmatter/body regexes also assumed LF line
  endings; the Cursor source files are CRLF, so the fence never matched and
  the body silently kept its raw YAML frontmatter block.
- Codex-generated skills baked in Cursor's colon slash-command spelling
  (`/cc:x`) for cross-references to other commands; Codex only understands
  `$cc-x`. Hand-written OpenCode and AGY command files had the same leftover
  colon spelling where they should read `/cc-x`.
- `agy` global preset install: `antigravity-cli/settings.json` was routed
  through `.agents/../antigravity-cli/settings.json`, which always resolved
  outside its containment root and refused the write. It now resolves
  against `~/.gemini` directly, matching `presets/agy/README.md`.
- `agy` hooks: `PreToolUse` fired on every file read (`view_file`), and the
  hook runner could emit two concatenated JSON documents on stdout when a
  candidate CLI wrote partial output before failing, corrupting the verdict
  the agent tries to parse.
- `substituteToolNames` hardcoded `\n` when rewriting frontmatter, silently
  converting CRLF files' frontmatter boundary to LF while the rest of the
  file stayed CRLF.
- `pagespeed-perf` skill (shared across claude/codex/cursor/opencode):
  an unquoted colon inside an `inputs[].description` value made its
  frontmatter invalid YAML ("Nested mappings are not allowed in compact
  mappings"), so the skill silently failed to parse wherever it was
  installed.
- Every generated flow command's rendered description carried a leftover
  `[cc: alias]` marker into 44 files: 40 across Claude's and Cursor's
  `commands/cc/*.md` sources, plus the 4 hand-maintained `ask` command copies
  (opencode, agy, codex, gemini) that don't go through the generator at all.
- `council` roster: the `security` member overlapped entirely with
  `security-reviewer` — same focus areas, but only `security-reviewer` carries
  the actual veto authority in `council-consensus.ts` — so it added a vote
  with no distinct behavior. Merged into `security-reviewer`.
- `install council --target gemini` wrote into `.agents/` (the agy
  installer's namespace) instead of `.gemini/`, even for a plain
  project-level (non-`--global`) install — Gemini CLI never received its own
  council skill or workflow.
- `install council --target cursor` silently produced no files at all
  (`default: continue` in the install target switch) — Cursor had no council
  support.
- `docs/current-status.md`: the published-package-version line had drifted to
  `1.1.0` against `package.json`'s actual `1.2.0`
  (`test/cc08-cli-contracts.test.ts` was failing on this before the fix).
- `rewriteTaskToolInvocation()` in `scripts/render-agent-commands.ts`: Gemini
  and Codex's generated commands (derived from the Cursor source) carried 34
  literal occurrences of "Invoke the `X` subagent via the Task tool" across
  21 commands — neither target has a Task tool. Rewritten to "Adopt the `X`
  role as defined in `<contextFile>`", the same phrasing Claude's own
  hand-authored commands already use for the identical reason. Regression
  test in `test/unit/scripts/render-agent-commands.test.ts` asserts every
  generated artifact never mentions "Task tool" again.

### Changed

- `getLatestSkillVersion()` (`src/core/presets/update-checker.ts`): now reads
  skill versions from `skills-registry.json` instead of scanning per-target
  `SKILL.md` files. Loads and caches the registry on first call.
- `version` field removed from frontmatter of 280 extended-shape `SKILL.md` files
  (249 under `presets/*/skills/`, 31 under `skills/`). Field is now sourced
  exclusively from the `skills-registry.json` registry.
- `council-*.md`/`.toml` per-agent files (agy, claude, opencode, gemini,
  cursor, codex) went from 34-line stubs (Role/Context/Focus Areas/4-bullet
  Responsibilities) to include a role-specific Review Checklist and the
  CRITICAL/WARNING/SUGGESTION finding format already used elsewhere in the
  repo, condensed from the real `architect`/`devil`/`security-reviewer`
  v1.0.0 agent contracts where one exists
  (`src/domain/council/council-agent.ts`).
- Gemini preset: `gemini.yml` now copies the full `opencode/skills` tree
  (was a 4-skill cherry-pick) and ships a `GEMINI.md` context file and
  `.gemini/settings.json`, matching every other target's parity.
- README's slash-command table reorganized into 4 tiers (Entry, Delivery,
  Verification, Management — 22 commands total) and 2 stale command-count
  mentions corrected.
- Every workflow command that has a natural successor (feature, fix,
  refactor, api-contract, db-migration, spec-mutation, review, council,
  test-plan, security — across all 6 targets) now ends with a "## Next"
  section naming it, so flows chain into each other instead of ending in
  silence.
- `ask` is no longer exempt from cross-target syntax checks: it was never a
  `WORKFLOW_COMMAND` (pure router, no CCEP bootstrap) and fell through every
  previous colon/hyphen/dollar syntax fix as a result.
- `src/presets/models/{claude,codex,cursor,gemini,agy}.yml` shrank to just
  `target:` (+ `permissions:` for opencode) — the 14-role model table and
  7-tool name mapping they all duplicated verbatim (4 of the 6 files were
  byte-identical except a comment and the `target:` line) now live once in
  `src/presets/models/roles.yml`; `loadModelConfig()` merges the two. No
  model, tool name, or role count changed — `test/model-config.test.ts`'s 26
  logic-level assertions (exact model slugs per role/provider, role counts,
  tools-vs-permissions shape) pass unchanged.
- The 4 `*/agent-contract-renderer.ts` files (claude, opencode, codex, agy —
  ~90 lines each of near-identical CouncilSpec/target validation) now
  delegate to a shared `renderAgentContract()` in the new
  `src/core/generation/agent-contract-renderer-base.ts`; each adapter is
  ~20 lines of target-specific config (path prefix, generator function,
  required dirs).
- The 6 `*-lsp-generator.ts` files' one shared line (`filter(lsp => lsp.status
  !== 'failed')` + early-return-if-empty) moved to `filterSuccessfulLsps()`
  in `src/core/lsp/lsp-config-utils.ts`. The JSON/YAML/TOML rendering itself
  stays separate per target — it genuinely differs (wrapper shape, syntax),
  not over-abstracted per the plan's own guardrail.
- `generatePermissionBlock`/`yamlString`, copy-pasted across up to 5 of the 6
  council generators, now live once in `src/domain/council/council-agent.ts`
  alongside `generateAgentContent`/`checklistFor`.
- `cc migrate`: a missing `.claude/settings.json` is no longer treated as an
  error — many projects (Gemini/Cursor-only ones, for instance) never had
  one. Only invalid JSON in an existing file still returns a non-zero exit
  code; a missing file now reports `settingsFileFound: false` and continues
  on to the orphaned-prompt-directory scan below.

### Added

- `skills-registry.json` (repo root): centralized single-source-of-truth for
  skill versions, validated by `SkillsRegistrySchema` (`src/validation/schemas.ts`).
  Path constant `SKILLS_REGISTRY_PATH` in `src/core/presets/package-paths.ts`.
- `scripts/migrate-skill-versions.ts`: one-time idempotent migration script that
  extracts `version` from 280 extended-shape `SKILL.md` files (249 in
  `presets/*/skills/`, 31 in `skills/`) and populates the registry while
  preserving exact line-ending style (CRLF or LF).
- `SkillFrontmatterSchema`/`validateSkillFrontmatter` (`src/validation/schemas.ts`)
  and `src/core/presets/skill-frontmatter.ts`: shared parsing/validation for
  every SKILL.md, tolerant of both the bare `{name, description}` and the
  extended `{id, name, description, ...}` frontmatter conventions already in
  use.
- `test/presets/frontmatter-parity.test.ts`: validates every shipped
  SKILL.md (presets/ sources plus the dogfooded `.agents`/`.cursor`/`.gemini`
  installed copies) against the schema and checks its identifier matches its
  directory.
- `test/unit/scripts/render-agent-commands.test.ts`: golden tests for
  `descriptionFrom`/`bodyFrom`/`rewriteCodexCrossReferences`/`renderGeminiToml`/
  `renderCodexSkill` against synthetic CRLF fixtures.
- `scripts/check-drift.ts` (`bun run check:drift`, wired into CI): regenerates
  the Gemini TOML and Codex skill commands and fails if the working tree
  still differs, catching hand-edited generated files or an uncommitted
  regeneration.
- `cc doctor`: validates all 6 target manifests against
  `InstallManifestSchema`, cross-target agent-role parity across
  `models/*.yml`, and installed skill frontmatter (scoped to skills
  CodeConductor's own manifest installs, not unrelated third-party skills
  co-located in the same directory).
- `installPresetCommand`: re-reads every rendered `template: true` file after
  a real (non-dry-run) install and reports (`postInstallWarnings`, non-fatal)
  any leaked `{{PLACEHOLDER}}` or invalid rendered SKILL.md frontmatter.
- `src/adapters/cursor/cursor-council-generator.ts` + `cursor-installer.ts`:
  Cursor now gets a council skill, per-agent role files, and workflow command
  under `.cursor/`, wired into `install.command.ts`'s target switch.
- `src/adapters/gemini/gemini-council-generator.ts` + `gemini-installer.ts`:
  Gemini gets its own native council routing — Markdown skill/agent files
  plus a native `.gemini/commands/cc/council.toml` workflow command — instead
  of piggybacking on the agy installer's `.agents/` paths.
- `test/presets/gemini-parity.test.ts`, `test/presets/readme-command-parity.test.ts`,
  `test/presets/ask-parity.test.ts`, and a "install council --target cursor"
  case in `test/cli.test.ts`.
- `docs/harness-spec.md` (CCHS v1): the skill/command frontmatter contract,
  the 3 cross-target invocation spellings, and the target-capability-matrix
  and skills-registry ideas the spec calls for but this pass does not build
  (documented as planned, not implemented).
- `CommandFrontmatterSchema`/`validateCommandFrontmatter` (`src/validation/schemas.ts`)
  and `parseCommandFrontmatter` (`src/core/presets/skill-frontmatter.ts`):
  validates every Markdown command's frontmatter (cursor/claude/opencode/agy)
  the same way `SkillFrontmatterSchema` validates every `SKILL.md`, wired into
  `test/presets/slash-parity.test.ts`.
- `cc migrate`: repairs a Claude Code `settings.json` left over from before
  the A6 fix above — rewrites every `Write(path)` permission rule to
  `Edit(path)` and dedupes the result, since a plain reinstall can't remove a
  bad rule already on disk (`mergeDeep`'s permission arrays merge by union,
  they don't replace). `--dry-run`, `--global`, and `--file <path>` supported.
  Now also detects and deletes orphaned `.{target}/prompts/v{old}/`
  directories (`findOrphanedPromptVersions()` in `src/commands/migrate.command.ts`)
  — leftovers from before a project's installed manifest pointed at the
  current prompts version, which `copyFromManifest` never removes on its own
  (it only adds/overwrites the current version's files). Reported/removed
  under the new `orphanedPromptVersions`/`orphanedPromptVersionsRemoved`
  response keys, added alongside the existing ones (`file`/`changed`/
  `rewritten`/`duplicatesRemoved` are unchanged for backward compatibility).
- `skills/` (repo root, new): canonical source for the 29 skills verified
  byte-identical by sha256 across every target that ships them (evaluation,
  openspec, using-cc-skills, testing-tdd, workflow-orchestration-patterns,
  20 `security-*` skills, and 3 others) — down from the plan's estimated 46
  after actually hashing every `SKILL.md` instead of grouping by name; 40
  same-named skills turned out to have genuinely different content per
  target (mostly stack-specific skills like `python`, `django-orm`,
  `spring-boot-kotlin`) and were deliberately left alone rather than
  collapsed. `src/presets/shared-skills.yml` lists which targets each
  canonical skill ships to; `scripts/sync-shared-skills.ts`
  (`bun run sync:skills`) copies it out to each — a no-op today since the
  copies already matched, verified by `test/unit/scripts/sync-shared-skills.test.ts`.
  `check:drift` now also fails on a hand-edited copy.
- `src/presets/targets/<target>.yml` (7 files) + `TargetCapabilitiesSchema` +
  `loadTargetCapabilities()` (`src/core/presets/manifest-loader.ts`): the
  target capability matrix `docs/harness-spec.md` §4 called for, validated by
  `cc doctor` and `test/unit/core/presets/target-capabilities.test.ts`.
  Declares each target's invocation spelling, command format, context file,
  and `subagentInvocationStyle` (`task-tool` / `adopt-role` /
  `invoke-with-context`) — the last one is checked against real content in
  each target's own commands, not just asserted.
- **Pi target** (`pi.dev` — `earendil-works/pi`, the coding-agent CLI, not
  Inflection's Pi): the 7th preset target. `src/presets/manifests/pi.yml`,
  `src/presets/models/pi.yml`, `src/presets/targets/pi.yml`,
  `presets/pi/AGENTS.md`, `presets/pi/settings.json`, and
  `src/adapters/pi/{pi-council-generator,pi-installer}.ts`, wired into
  `install.command.ts`'s target switch. Registered as an `IndividualRunnerTarget`
  across `runner-target.ts`, `schemas.ts`'s enums, `command-invocation.ts`,
  `update-checker.ts`, and `preset-resolver.ts` — the union type that had to
  be repeated inline at each of those call sites now has one source
  (`IndividualRunnerTarget` in `runner-target.ts`), so adding an 8th target
  won't require re-finding every occurrence by hand again.
  - Verified against Pi's own published docs
  (`github.com/earendil-works/pi/packages/coding-agent/docs/`), not a live
  install (no Pi binary available to test against — the same caveat the
  original plan flagged): skill discovery at `.agents/skills/` (shared with
  agy — confirmed directly in Pi's skills.md), prompt templates at
  `.pi/prompts/*.md` with the filename as the command name and native
  `$ARGUMENTS` support (no placeholder translation needed, unlike Gemini's
  `{{args}}`), and settings at `.pi/settings.json`.
  - Pi has no Task tool, subagents, or MCP support — a deliberate design
    choice stated in its own docs, not a gap. Its commands come from
    `opencode/commands` (byte-compatible: same hyphen invocation, same
    "invoke `X` with `<context>`" phrasing opencode already uses for the
    identical reason), so no rewriting was needed.
  - `roles.yml` gained a `pi:` model column, copied verbatim from `claude:`
    (Pi is provider-agnostic and Anthropic model IDs are stable across
    clients) — `ModelConfigSchema.agents[role]` now accepts a `pi` key.
  - `test/pi-preset.test.ts` (19 tests) + 3 new cases in
    `test/unit/core/presets/target-capabilities.test.ts` and
    `test/cli.test.ts`.

### Removed

- `presets/opencode/prompts/v0.1.0` through `v0.6.0` (52 files, 6 directories)
  — deprecated agent-contract snapshots no install path has read since
  `preset-resolver.ts` and every manifest moved to `prompts/v1.0.0`. Deleting
  them first required migrating the 4 test files that referenced them by
  literal path:
  - `test/prompt-v050.test.ts` and `test/prompt-v060.test.ts` (deleted
    outright — every assertion in both was about frozen v0.5.0/v0.6.0
    content). The two assertions in the former that actually tested *active*
    content (`presets/opencode/agents/*.md` reflecting v1.0.0; `codex/AGENTS.md`'s
    DDD→SDD→TDD routing row) moved to the new
    `test/active-agent-contracts.test.ts`.
  - `test/routing-order-parity.test.ts`: removed the 8 `v0.5.0`-path entries
    from `ROUTING_SURFACES` (the other 20 entries test a still-live invariant
    and are untouched).
  - `test/cursor-preset.test.ts`: updated the `Evaluation Gate (v0.5.0)`
    assertion to `v1.0.0` to match the header fix below.
- 11 `presets/cursor/agents/*.md` files carried a stale `v0.5.0` header
  (`# Agent Contract — X v0.5.0`, plus `contract_version: v0.5.0` in
  scorecard-metadata instructions) left over from when Cursor's contracts
  were first copied out of the then-current opencode snapshot; bumped to
  `v1.0.0` (16 occurrences) — these files are Cursor's own independently
  maintained contracts, not derived from opencode's, so this is a label
  correction, not a content merge.
- Stale dogfooded copies of the same deprecated snapshot,
  `.agents/prompts/v0.5.0/`, `.cursor/prompts/v0.5.0/`, and
  `.gemini/prompts/v0.5.0/` (12 files each, 36 total) — orphaned in this
  repo's own working tree from before its manifests pointed at `v1.0.0`, and
  unreferenced by any current install path.
- `docs/prompt-versioning.md`: the "never delete a previous version" /
  "rollback is always possible" rules never matched what the code actually
  does (no install path ever read a pinned old version) and blocked this
  cleanup on a technicality; rewritten to state the real guarantee (`v1.0.0`
  is the only version shipped and reinstallable) with an explicit amendment
  note recording why the six directories above were deleted instead of kept
  indefinitely.
