### Added

- `goal` command (alias: `cc-goal`) — decomposes an objective string into a
  dependency-ordered task graph using template matching (auth, crud, search,
  notification, migration) with generic fallback. Writes
  `.codeconductor/current-goal.yml` for orchestrator consumption.
- `goal-planner` agent — deterministic template matching, produces YAML task
  graph with explicit `depends_on` references.
- `src/core/goal/` module — `goal-planner.ts` (template matching) and
  `goal-state.ts` (graph validation, cycle detection, YAML persistence).
- `depends_on` field in Task Card template — optional list of task IDs for
  dependency-ordered delegation by the orchestrator.
- Dependency-order delegation rules for orchestrator — tasks are routed only
  after all `depends_on` targets complete with status `done`.
- `contract-builder` agent — defines API contracts, data shapes, and behavior
  specs before implementation. Produces OpenAPI specs, JSON Schema, or
  TypeScript interfaces as the source of truth for implementer and tester.
- DDD→SDD→TDD pipeline in routing table —
  `contract-builder` → `architect` → `implementer` → `tester`.
- TDD Loop Guard — orchestrator tracks failed implementer→tester iterations;
  halts at 3rd consecutive failure, marks task `blocked` via `markTaskBlocked()`,
  and emits escalation report.
- Escalation emitter — `writeEscalationReport()` writes
  `.codeconductor/escalated-<taskId>.json` with iteration history, error log,
  attempted fixes, and recommended action.
- `blocked_reason` field in goal state schema — records why a task was blocked
  by the TDD Loop Guard.
- Routing Policy bumped to v0.3.0.
