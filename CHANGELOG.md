### Added

- CCEP workflows `explore`, `triage`, `prototype`, `handoff`, and `clarify`
  (`/cc-explore` / `/cc:explore`, and the same pattern for the others) — map
  the repo, classify incoming work, run a disposable spike, compact a session,
  or restate a deliverable.
- CCEP workflow `iterative` (`/cc-iterative`, `/cc:iterative`) — wayfinding
  (graphify + repo-explorer), Relentless Grilling intake, contract + design,
  test-before-implement, council review, and docs. Orchestrator v1.0.0 lists the
  command; `council` now starts with a wayfinding phase.
- Agent Contracts `prompts/v1.0.0/` — first stable, distributable set, copied and
  improved from `v0.5.0`.
- New `devil` contract — the devil's advocate role required by the `council`
  workflow profile (previously referenced without a contract).
- New `planner` contract (CCEP-1 intake) finalized from the `v0.6.0` draft.
- CCEP-1 "structured output" section on every `v1.0.0` contract, mapping each
  Markdown Deliverable to its runtime JSON schema.

### Changed

- Orchestrator contract now documents the `council` workflow, the `devil`
  routing row, a workflow-commands table, and the CCEP-1 confirmation gate.
- `feature` and `fix` workflow profiles start with a `wayfinding` phase
  (`repo-explorer`) before intake.
- Prompt version markers and scorecard `contract_version` bumped to `v1.0.0`.
- Task Coach contract (`v1.0.0`) gained a Grilling protocol: stress-tests each
  assumption with one adversarial question before accepting a Task Card;
  unresolved grill questions populate `questionsForUser`/`needsConfirmation`
  so the existing `ConfirmationGate` halts the flow. `/cc:feature` Step 1 now
  names the `ConfirmationGate` explicitly instead of generic wait-for-human
  prose.

### Deprecated

- Agent Contracts `v0.1.0`–`v0.4.0` marked deprecated (kept append-only for
  reproducibility); `v0.5.0` and `v0.6.0` superseded by `v1.0.0`.
