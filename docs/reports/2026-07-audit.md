# Informe de auditoría — CodeConductor (2026-07)

**Fecha:** 2026-07-26
**Alcance:** proceso de implementación, documentación, calidad del flujo de
agentes y cobertura de código.
**Versión analizada:** `0.5.0`.

---

## Resumen ejecutivo

El código es sólido: TypeScript en modo `strict`, validación con Zod, patrón
`Result<T, E>`, jerarquía `CliError` con exit codes bien definidos y una
arquitectura por capas clara (`cli → commands → core → domain → infrastructure`).
Dependencias mínimas (`zod`, `yaml`). No se observaron `any` ni `TODO` en el
código de producción revisado.

El hueco principal es **cobertura de tests**: ~24-25K LOC en `src/` con 49 tests
**solo de integración** de la CLI (`test/cli.test.ts`) y **cero unit tests**. La
cobertura estimada estaba en torno al 6-12%. No existía gate de cobertura ni el
CI ejecutaba `check:prompt-changelog`.

Esta auditoría acompaña a un cambio que: (1) añade infraestructura de cobertura
(Bun nativo, sin dependencias nuevas), (2) arranca una suite de unit tests por
olas de criticidad, y (3) crea la documentación faltante.

manteniendo un barrel `schemas.ts` que reexporte para no romper imports.

## 4. Cobertura — plan de olas

La cobertura del 70% (línea y función) se persigue por olas priorizadas por
ROI/criticidad. El gate en `bunfig.toml` se activa **solo** cuando la medición
real (`bun test --coverage`) alcanza el umbral, para no dejar el CI en rojo.

1. Lógica pura / alto ROI: `utils/result`, `utils/logger`, `cli/errors`,
   `validation/schemas`, `domain/council/council-consensus`.
2. Detección y config: `core/detection/*`, `core/config/*`, `core/runner/runner-target`.
3. Filesystem / seguridad: `core/filesystem/{credential-guard,safety,file-writer,safe-merger}`.
4. Presets y manifests: `core/presets/*`.
5. CCEP: `core/ccep/*`.
6. Adapters: generadores council por target.
7. Dominio restante: `domain/seo/*`, `core/goal/*`, `core/product-graph/*`,
   `knowledge/*`, `infrastructure/http/safe-fetch`, `parsers/*`.

**Regla de cierre:** si tras las olas 1-7 no se alcanza el 70%, se fija el
umbral en el valor real medido como ratchet documentado y se avisa; no se fuerza
un CI rojo. El objetivo comprometido sigue siendo 70%.

## 5. Infraestructura añadida (sin dependencias nuevas)

- `bunfig.toml`: sección `[test]` con `coverageReporter = ["text", "lcov"]`,
  `coveragePathIgnorePatterns = ["src/presets/", "test/"]` y `coverageSkipTestFiles`.
  Medición real: **77.0% líneas / 78.1% funciones** (excluyendo `src/presets/`), por
  encima del objetivo, así que el `coverageThreshold = { line = 0.70, function = 0.70 }`
  queda **activo** (el gate falla por debajo del 70%).
- `.github/workflows/ci.yml`: `bun test` → `bun test --coverage`; nuevo paso
  `bun run check:prompt-changelog`; subida de `coverage/lcov.info` como artifact.

Bun trae cobertura nativa (lcov), por lo que no se introducen dependencias.
