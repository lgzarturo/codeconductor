# v1.0.0 Release Notes — Product Operating System

**Status:** Draft for the **v1.0.0 Product OS surface**. `package.json` is
`1.0.0`; capabilities marked unreleased in `docs/current-status.md` are still
library-only or undocumented as shipped CLI.

**Target date:** TBD

## Summary

CodeConductor v1.0.0 evolves from agent orchestration prompts to a **Product
Operating System**: structured product memory, executable orchestrator runtime,
impact analysis, verification with evidence, and a feedback loop — all file-based
in `.codeconductor/`.

## New CLI commands

| Command | Purpose |
| ------- | ------- |
| `cc ingest` | Build product graph from README, ADRs, backlog, src, graphify |
| `cc product graph\|query\|path\|timeline\|memory\|decisions\|insights\|export` | Product console |
| `cc orchestrate status\|next\|run\|cycle` | Goal DAG runtime |
| `cc impact --files\|--node\|--capability` | Blast-radius preview |
| `cc verify --task <id>` | Evidence-gated verification |
| `cc goal "<obj>" --product` | Product-aware planning |
| `cc ccep consensus --input @verdicts.json` | Council ballot-box gate (0/1/2) |
| `cc ccep taskcard --command <wf> --input @card.json` | Canonical TaskCard intake gate |
| `cc openspec start\|done\|block\|archive` | Close the OpenSpec delivery loop |
| `cc scorecard catalog\|fingerprint\|experiment\|ablation` | Leave-one-out harness measurement (no LLM) |

## Contracts closed in this draft

- OpenSpec `start` / `done` / `block` / `archive` write BACKLOG.md and
  `openspec-state.json` atomically; illegal transitions fail closed.
- Council majority now requires quorum (3 without roster), explicit confidence,
  and applies `criticalFindingsPolicy` (default escalate). Derived security veto
  covers critical findings in security/auth/injection/credentials/supply-chain.
- Canonical TaskCard is the delivery source of truth. OpenSpec cards stay a
  phase view. Pipeline TaskCard round-trips Canonical without dropping
  boundaries (`scope.out`).
